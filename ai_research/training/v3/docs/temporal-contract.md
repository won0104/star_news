# 7번 Time 학습·정규화·attachment 계약

5번 `time_mention`은 정규화 값과 무관하게 exact textual span을 추출한다. 7번 `TimeGoldAdapter`는 같은 단일 backbone/공유 DCE lease의 Event/Time source 표현을 소비한다. `normalized_value`가 있는 Time만 format과 **전체 문자열** 문자 CE로 감독한다. `null`은 value loss에서만 제외한다. Event×Time의 실제 Gold attachment를 양성, 다른 eligible pair를 결정적 표본 음성으로 학습한다. 같은 문장/기사 공기만으로 edge를 만들지 않는다. Statement에는 Time 필드를 추가하지 않는다.

`parse_canonical_time`은 유효한 `YYYY`, `YYYY-MM`, `YYYY-MM-DD`, `FYyyyy`, 같은 granularity의 정렬된 interval을 원형 그대로 보존한다. 윤년과 실제 월/일 범위를 검사한다. `infer_source_time`은 명시적 ISO·한국어 연/월/일, raw operator를 보존한 명시적 `~부터`/`~이전`/`~이후` anchor, 정확한 timezone을 가진 `published_at`과 원문의 `오늘`/`어제`/`지난달`을 해석한다. day만 있는 `지난 N일`은 `RelativeMonthContext`가 명시적으로 제공될 때만 정규화한다. context는 caller가 문맥으로 확인한 발행 연·월(`PUBLISHED_AT_MONTH_CONFIRMED`) 또는 기사 내 exact `YYYY년 M월` span(`SOURCE_EXPLICIT_MONTH`)과 evidence ID를 가져야 한다. `requested_day <= published_day`만으로 발행월을 자동 적용하지 않는다. r06.0의 2025-10-31 문맥을 명시적으로 확인한 경우에만 `지난 16일부터`와 `휴전 발효 6일 만인 지난 16일부터`를 `2025-10-16`으로 만든다. 확정 근거가 없으면 `MISSING_CONFIRMED_RELATIVE_MONTH`와 null을 유지한다. `SOURCE_RULE` closure는 mention에 보존된 같은 context와 exact 근거를 재검증한다. `최근`/`당시`, anchor·timezone 부재, 지원되지 않는 시각 표현은 `UNRESOLVED`다. article 발행일에서 무조건 Event 시간을 만들지 않는다. 학습된 문자 head의 임의 출력은 runtime calendar 값으로 직접 확정하지 않는다.

Serving caller는 `RelativeMonthContextBinding`으로 article ID·content SHA256·exact Time `[start,end)`·원문 text와 context를 함께 `V3ServingWorker.analyze(relative_month_contexts=...)`에 전달한다. worker는 `_analyze_owned` 진입 직후 article snapshot, Time span, `SOURCE_EXPLICIT_MONTH` 원문 span 또는 명시적으로 확인된 `published_at` 근거를 검증한 뒤 exact span key로만 context를 찾는다. 이 binding은 `infer_source_time` → `TimeMentionEvidence` → `close_time_occurrences`까지 같은 객체로 전달된다. binding이 없는 다른 Time span에는 같은 월을 전파하지 않고, 발행일만으로 `PUBLISHED_AT_MONTH_CONFIRMED`를 만들지 않는다. 입력 binding이 model의 accepted Time span과 일치하지 않으면 audit에서 unused로 남는다.

`TemporalOccurrence`는 exact grounding, 원래 precision, normalization 상태·사유, Event attachment, raw projection safety를 따로 보관한다. 상대 day 정규화에 쓴 `RelativeMonthContext`도 evidence ID, provenance, 연·월, exact source/published-at 근거와 함께 scalar occurrence와 serving audit에 남는다. 같은 source occurrence는 합치되 다른 granularity의 값을 강제 병합하지 않는다. `calendar_eligible`은 유효한 단일 YEAR/MONTH/DAY **값 형식**에만 true다. FY·interval·null은 내부에서 보존하며 calendar materialization 대상으로 속이지 않는다. `r06-time-public-projection-v1`은 명확한 calendar literal과 시작 anchor `~부터`만 allowlist하고, `~이전`, `~이후`, 근사·비교·기간·사건 기준 표현은 보수적으로 제외한다. `처음부터`, `2022년경부터`는 `부터` 문자열만으로 승격하지 않는다.

`public_calendar_candidate`는 occurrence 수준의 `실제 attachment AND calendar_eligible AND projection_safe`이다. PUBLIC은 또한 선택된 final Event의 `LocalTimeFact`를 확인한 뒤 같은 규칙을 재적용한다. Time node와 `OCCURRED_ON`은 같은 occurrence evidence로 함께 생성·제외되며, validator는 Time node의 raw evidence safety와 edge evidence 동일성을 다시 검사한다. PUBLIC에서 제외된 mention의 raw span, normalized value, attachment는 scalar construction/audit에 계속 남는다. 8번의 final Event ID가 정해지면 `remap_time_attachments`가 모든 member의 Time 근거를 cluster endpoint로 합친다.

기존 rc2에서는 `temporal_consolidation.py`가 accepted source family에서 V1 normalization을 형식 선호에만 사용하고 미정규화 family도 유지한다. `compact_assembly.py`는 V1 미정규화 occurrence에만 V2를 적용하며 기존 V1 값을 덮지 않고 pending attachment를 remap한다. 새 v3 경로는 그 우선순위/미정규화 보호 원칙을 지키되 기존 서비스 serializer를 이번 단계에서 수정하지 않는다.

예측 attachment는 `EventTimeFeatureLease` 안에서만 점수화하며 임시 `score_threshold=0.0`, 4,096 pair cap에 걸리면 `partial`을 반환한다. 이 값은 서비스 threshold가 아니다. lease는 마지막 tensor consumer 뒤 닫고 scalar `TemporalOccurrence`에는 tensor를 넣지 않는다. 실제 pretrained checkpoint load나 서비스 quality/latency 측정은 수행하지 않았다.

`time-coverage-report.json`의 기존 train 400기사 정적 수치: Time span 3,257, normalized 1,733, unresolved 1,524, Event-Time 양성 2,302(이 중 null value 900), 유효 음성 universe 43,256, 정규화됐으나 미연결 Time 716. 이는 Gold 구조 계수이며 예측 정확도나 threshold 근거가 아니다. dev/test Gold는 사용하지 않았고 단계 2의 dev Gold blocker가 남아 있다.
